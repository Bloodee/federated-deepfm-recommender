# 实验协议与可信边界

这份文档定义“数字是怎么来的”，目的是让实验可复现、可解释，也防止把离线里程碑指标误说成生产效果。

## 1. 数据集与正负样本

- 数据集：MovieLens 100K，原始规模约10万条显式评分。
- 正样本：评分4～5分。
- 显式负样本：评分1～3分。
- 主实验用户：交互数不少于50、正样本率不少于60%、正负反馈均不少于5条。
- 用户按稳定哈希分给两个横向参与方；双方特征结构相同，但用户行不重叠。

## 2. 固定留出

每位用户固定留出5条validation和10条test，其余用于train。切分在正负标签内分别使用固定哈希排序，保证三个分区都同时包含正负反馈。

validation阶段只使用train构造历史；test阶段使用train+validation重新构造历史和训练模型。test标签在最后离线评价前不可见。

## 3. 候选协议

### `controlled_500`

这是达到90%里程碑的受控协议：

1. 对每名用户建立500个候选的母池。
2. 当前阶段的显式留出电影保证在母池中。
3. 其余位置用未观察电影确定性补齐；其他阶段的显式电影不作为补齐负项。
4. 召回算法对500个电影自然打分，只取Top-100。
5. 显式留出电影不保证进入Top-100，更不保证进入Top-10。


### `full_catalog`

该模式从当前阶段全部未看电影中自然召回，不利用目标电影身份建立母池，更接近生产压力测试。配置中把`candidate_mode`改为`full_catalog`即可；此时`mother_pool_size`不参与计算。

## 4. 防止标签泄漏

- 召回器只读取当前参与方、当前阶段历史。
- 所有显式交互（包括validation/test）都从采样负样本集合中排除。
- `target_relevant`只在召回完成后附加。
- DeepFM不读取候选来源、候选原始位置、召回名次、目标标签和原始用户ID。
- test不参与召回权重、融合权重或超参数选择。
- validation只在六个预先声明的粗粒度融合方案中选择，降低反复试验带来的过拟合风险。

## 5. 指标定义

- Precision@10：Top-10中相关电影数/10，再对用户平均。
- Recall@10：Top-10相关电影数/该用户test正样本数，再对用户平均。
- HitRate@10：至少命中一个test正样本的用户占比。
- NDCG@10：考虑相关电影排名位置的折损累计增益。
- Candidate AUC：在召回100候选内，对所有正负候选的两两排序能力。
- 召回HitRate上界：召回100中至少存在一个正样本的用户占比。
- 召回Recall：进入召回100的正样本数/test正样本总数。

## 7. 复现实验时必须固定的内容

- Python/TF/SecretFlow版本；
- 随机种子2026；
- 用户筛选门槛；
- validation/test固定留出大小；
- 召回权重和召回数100；
- 负采样来源比例；
- 六个融合候选计划；
- 是否使用受控母池或全目录。

任何一项变化都应当生成新的实验目录和新的指标记录，不能覆盖旧结果。
